# 每日模型费用预估

测算日期：2026-10-01。单位为人民币。本文估算基于当时的只读数据库检查及公开价格；2026-10-02 另进行了三个社区的小批真实试跑，保守估算约 0.14 元，结果见[真实试跑记录](live-preview.md)。小批费用不能直接替代完整一天的用量测算。

2026-10-02 为改善译文自然度，推荐配置又增加了 DeepSeek Flash 对照原文的母语审校。**下文的日费与首次补译估算只包含千问初译，尚未计入这一步费用，不能当作当前完整配置的日费。** 小预算重新处理的五篇样本及累计成本另记在[试跑记录](live-preview.md)；其中包含调试重试，不能按五篇的平均费用直接推算日常成本。文风策略升级后，已有完整译文仍可读，历史补译应另外限制批次和预算。

精简后的默认配置为 **88 个启用入口**。按每天 150–350 条新增、公开正文均长约 6,000 字符的规划假设，日常模型费用暂估 **5–12 元/天**，每月按 30 天约 150–360 元。典型取每天 250 条，约 **7 元/天**。这是尚未用新配置实跑验证的估算，不是实测账单或硬性费用上限。

精简前 100 个启用入口的原估算为 15–30 元/天，典型 600 条约 22 元/天，下文保留作对照。两次估算使用不同的新增量和正文长度假设，不能据此保证实际节省比例。修改仍在新 worktree；新模型组合已完成独立小批真实试跑，原运行服务尚未应用信源调整，88 个启用入口也尚未整体运行满一天。

## 精简后的用量假设

- 默认 88 个入口：77 个参与内容处理，11 个只提供热度信号；59 个 RSS / Atom、14 个网页列表、15 个 JSON 列表，不需要付费列表接口凭证。初始间隔对应约每天 1,584 次列表检查，自动调频后可能变化；检查列表本身不等于调用模型。
- 晚间 22:03:50 的旧库只读快照中，80 个重合入口近 24 小时新增 340 条非历史内容。其中三个 GitHub 仓库泛搜索有 210 条、Habr 综合频道有 62 条，另有 Codex issue 查询 24 条及 Console.dev 8 条，均在本轮暂停名单中。这些来源包含已经精选的好文章，不能将 304 条全部解释为低质量或无损可省。
- 这只是旧服务的短窗口。新接入社区还有 17 个启用入口，尚未完整运行一天。暂用每天 150–350 条作为容量假设，典型 250 条；75% 有公开全文，均长取 6,000 字符，反映长 README 入口暂停及社区短帖占比增加的预期，正文长度也仍需实跑校正。
- 保守沿用旧回执的分析环节平均 Token 用量、每篇两次评分和 95% 预筛通过率，暂未把收紧预筛的潜在节省计入。公开全文和卡片翻译按现有公开内容覆盖要求计算，**不因预筛 BLOCK 或未入精选而打折**。

## 每天 250 条的计算

全文按约 188 篇、每篇 6,000 字符计算，约 112.5 万原文字符。保留原语言，补齐另两种语言。沿用下文的两目标输入合计 0.60 Token / 原文字符、输出合计 0.57 Token / 原文字符，另给包装和分块留 15%。

| 环节 | 典型每天费用 |
|---|---:|
| 千问预筛、结构抽取 | 约 0.3 元 |
| DeepSeek 两次评分、理解、摘要、归组、综述及报刊 | 约 2.9 元 |
| 千问全文、卡片、事件和报刊翻译 | 约 2.5 元 |
| 分组召回所用向量模型 | 约 0.1 元 |
| 小计 | 约 5.8 元 |
| 额外预留 20% 的重试、修订及用量偏差 | 约 1.2 元 |
| 合计 | **约 7 元/天** |

便于复算：千问分析沿用旧典型费用 `0.7814 × 250 / 600`；DeepSeek 扣除原报刊等预留后按条数缩放，`(6.7182 - 0.6) × 250 / 600 + 0.35`。全文翻译为 `1.125 × (0.60 × 0.70 + 0.57 × 1.95) × 1.15` 元，另给卡片、事件和报刊翻译约 0.5 元；向量约 0.1 元。最后乘 1.20，约 6.97 元。

如果实际公开正文均长仍有 12,000 字符，250 条情形约为 9–10 元/天；若同时接近 350 条，可能到 13–15 元/天或更高。不应为了兑现费用区间而删掉高价值长文或跳过全文语言覆盖。上线后应分别看新增量、公开正文字符量、精选质量与真实模型回执，再修正预算。

精简依据、覆盖代价及应用方式见 [信源精简](source-pruning.md)。暂停入口只减少后续采集，已排队内容与历史公开文章仍可能继续消耗模型额度。

## 精简前的用量快照

- 配置中 100 个启用入口，89 个参与内容处理，11 个只提供热度信号；全部为 RSS、网页或 JSON 接口，30 个 X 入口仍暂停，没有启用付费列表接口。
- 初始间隔对应每天约 1,806 次列表检查。每天 04:20 会自动调整间隔，检查次数可能增加。重复且未变化的内容不会因为又检查一次列表就重新分析。
- 旧数据库覆盖其中 80 个入口。21:31 的只读快照显示，这些入口近 24 小时新增 332 条非历史内容，近 6 小时为 91 条；最近 250 条已公开且有全文的样本，平均正文约 17,202 字符。本文另一份 22:03 快照新增量为 340 条，两个时点的数字不混用。
- 另外 20 个社区入口尚未完整运行一天，不能把静态 RSS 返回条数当作每天新增量。暂按所有入口合计每天 500–800 条新增内容规划；典型情形取 600 条。新增社区短帖较多，典型公开正文均长取 12,000 字符，75% 的新增条目最终有公开全文。
- 旧服务仅运行一天多，期间有首次历史导入。这里采用非历史条目及真实回执的平均 Token 用量作参照，没有将初始化总费用视为稳态日费。

## 精简前每天 600 条的计算

按 90% 的新增条目进入内容处理、预筛通过率 95%、每篇两次评分计算。真实非历史回执参照值：预筛平均输入约 4,560 Token，结构抽取约 2,432；评分每次输入约 7,007、缓存命中约 4,825；内容理解输入约 8,680，普通摘要约 3,881。写作按 65% 理解、35% 普通摘要分配，输出同样采用回执均值。

全文按 450 篇、每篇平均 12,000 字符计算，共 540 万原文字符。保留原语言，为另两种语言生成译文。旧全文翻译回执中，两种主要目标语言输出合计约为每原文字符 0.56 Token；测算取 0.57，两个目标的输入合计取每原文字符 0.60 Token，另给 HTML 包装和分块预留 15%，并增加卡片、事件和报刊翻译用量。这些是近似转换率，不能代表每篇文章或新模型的准确 Token 数。

如果新增量翻倍，或集中出现长文，费用可能达到 40–60 元/天甚至更高。没有新内容且没有待处理历史内容时，例行检查不会产生这些模型分析费用。现有预算主要限制请求次数，以上人民币预算并非已配置的每日金额封顶。

## 首次启动与补译

两种情况分别计算，不相加：

- 空库首次启动：当前 88 个入口各限制初始回灌最多 8 条，理论上限 704 条；它们在前次实抓快照中接收合计 658 条，数据库判重后可能更少。这是当时列表的存量样本，不是当前的新一轮导入实测。按本轮较短正文假设，初始化额外约 15–25 元；若正文仍接近原 12,000 字符假设，则应保留 20–40 元预留，可能分多天处理完成。
- 沿用旧数据库：此前只读快照中，与精简前信源重合的公开条目有 1,855 条，其中约 1,682 条有正文，正文合计约 1,727 万字符。暂停信源不删除这些公开条目，已有正确译文继续复用；补齐历史公开全文和缺失语言，一次性仍暂预留 30–60 元。实际费用取决于切换时的已完成缓存、正文代码占比和修订情况。

日常费用不包含服务器、域名、代理、以后启用的 X/公众号等付费采集，以及另行配置的付费正文兜底。本文也没有验证新模型的语义效果；启动前仍需用同一批三语样本对照旧结果。
