# 多语言排查与修复

本次修改位于 `codex/worktree-20261001`，公开站点支持中文、英文、俄文。代码尚未提交或部署，未修改线上数据，也未调用真实付费模型。

## 已确认的根因

| 范围 | 原有问题 | 修复后的行为 |
|---|---|---|
| 文章正文 | 自动翻译只处理近期、部分入选文章；旧内容和未入选内容被排除 | 后台任务分批扫描全部公开内容，优先入选文章 |
| 文章阅读入口 | 页面没有完整的三语切换入口；从原文页切换仍停留在原文 | 每篇文章提供中、英、俄入口及原文入口，全局切换同步选择对应正文 |
| 内容语言兜底 | 俄文缺译时可能显示英文；摘要夹带中文推荐理由 | 只读取所选语言的有效译文，缺译明确提示，并标注实际显示语言 |
| 翻译覆盖 | 容器文字、超长单段可能漏译；整体字符上限截断长文章 | 翻译文字节点，保留 DOM、链接、行内格式及代码；超长节点分段，按任务时间预算续传 |
| 翻译失败 | 部分失败达到次数上限后不再重试；无效缓存可能被视为完成 | 失败按语言退避，普通失败等待十五分钟，多次失败等待一天；无效、过期或不完整结果重新排队 |
| 标题、摘要、理由 | 只处理近期记录；仅有原始标题的文章缺少中文补译 | 按原始字段语言生成缺失的指定语言，标题型文章保持摘要为空 |
| 事件、日报 | 历史记录不补译；日报引用标题与摘要没有纳入翻译快照 | 翻译完整快照中的正文和引用文案，保持标识、链接、排序及历史快照一致 |
| 菜单与标签 | 分类、主题、主体、筛选标题、收藏快照、日报版头存在固定文案 | 公开界面文案随语言切换，筛选仍使用稳定的原始键 |
| 关于页 | 最近精选接口忽略语言；统计缓存可能留住撤回的标题 | 经 publication 读取当前精选并本地化，统计计数继续缓存 |
| 更新日志 | 新条目的标题与正文只能依赖全局字典，不能附带完整翻译 | 条目可自带 `translations.zh/en/ru`，兼容原有字典条目，并去掉示例中的旧品牌 |

固定词典、分类及公开页面文案经过检查。品牌名、来源名、产品标识、链接、代码和语言选择器中的语言自称保留原始写法。管理员后台仍使用中文，未加入公开站点的三语路由。

## 历史内容补译

部署时先执行新增的向后兼容迁移 `0041_translation_coverage.sql`。迁移只增加覆盖版本字段，不删除正文或已有译文。旧模型译文会在后台逐步重新核查，原始来源内容保留。

既有 worker 的 `content.localize`、`stories.localize`、`reports.localize`、`content.translate` 每五分钟运行。移除日期窗口后，这些任务会分批处理历史公开内容；每轮有条数或时间预算，所有模型请求仍经过付费回执和预算熔断，读者打开页面不会触发模型调用。

缺译、部分译文或任务失败会明确展示状态。代码修复不代表现有线上历史文章已经翻译完成；补译速度取决于 worker、模型配置、预算以及内容长度。无正文可用的文章会标注正文不可用。
