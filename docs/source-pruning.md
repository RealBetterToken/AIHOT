# Vibe Coding 信源精简

调整日期：2026-10-01。目标是减少与程序员使用 AI 开发软件关联较弱的材料、泛搜索和重复入口，保留活跃社区的实践与讨论、官方变化及原创工程经验。

默认启用入口从 **100 个降到 88 个**，新增暂停 12 个。总配置仍为 151 个，63 个暂停；不删除信源或历史文章。评分的五个维度、权重和精选门槛未改。此次只修改新 worktree 中的配置、相关性预筛提示词与文档，未修改原服务数据库或重启原 worker。

## 真实产出依据与局限

2026-10-01 22:03:50（北京时间）只读检查旧服务数据库。与精简前配置重合的 80 个入口，近 24 小时新增 340 条非历史内容：

- 三个 GitHub 仓库泛搜索合计 210 条，占 61.8%；各入口已有正文的平均长度约 1.7 万至 2.4 万字符，其中 7 条已经进入精选。
- Habr 的两个综合频道合计 62 条，占 18.2%；其中 6 条已经进入精选。
- 再加 Codex issue 查询的 24 条、Console.dev 的 8 条，本轮暂停入口合计带来 304 条，占这次快照的 89.4%。其他本轮暂停入口在这一旧数据库窗口内没有新增或尚未接入。

这些入口有有价值的内容，暂停依据是范围和持续处理效率，不是“所有文章都差”。旧服务只运行了一天多，这不是长期统计；其余新接入社区尚未完整运行，**89.4% 不能当作新配置未来的减量或节省比例**。不以一天没有发文为由移除原创作者，也不根据短窗口的精选数调整评分门槛。

采集可用性依据为 [13:23 的全量实抓快照](source-fetch-check.md)：当前 88 个启用入口均在当时通过集合中，采集地址和字段没有改动。此次只复核配置与该记录的对应关系，没有重新对 88 个入口发起全量网络请求。过去通过不保证今后始终可用，线上仍需观察抓取失败、限流和内容抽取结果。

## 保留的范围和预筛调整

保留 Hacker News、Reddit、DEV Community、V2EX、CSDN、稀土掘金、Habr、Tproger 和 Cursor Forum 的已验证入口。DEV 的 AI Coding 标签样本包含 gstack 工程实践与 AI 代码归属讨论，继续保留；不能因为同一标签混有一条泛新闻就移除整个主题。Tproger 和 HN MCP 等仍有泛内容，交由相关性预筛逐条处理。

当前 88 个入口中，77 个参与精选候选处理，11 个只提供热度信号。77 个候选入口里 33 个带社区标签；其余包括官方、原创作者和专业工程材料。入口数量不等于每天文章数或页面内容占比，低频而有用的博客无需为了凑固定数量删除。当前初始间隔对应约每天 1,584 次列表检查，后续仍沿用自动调频。

预筛要求材料与程序员使用 AI 开发软件有实质联系。保留工具和模型变化、开发 Agent、Skills / MCP / Hooks、配置与工作流、故障和事故、AI 代码测试与评审、团队工程方法。消费助手、办公和广告 Agent、图像影音、普通数据库或语言教程不能只凭 LLM / Agent / MCP 字样放行。简短的真实经验或问题仍可相关；缺正文时，明确 AI 编程标题可通过，其余信息不足的材料保留待补，不直接丢弃。

质量评审仍由原评分流程负责。预筛 BLOCK 不再进入评分与写作，但已有公开卡片和全文仍按原规则补译，不能把预筛拦截比例直接当作全文翻译节省比例。预筛提示词的语义效果尚未经过真实新模型样本对照；离线测试只能验证调用协议、状态处理和回归行为。日常候选量先按 150–350 条规划，这是假设，不是已测产量或发布硬上限。费用假设见 [模型费用预估](model-cost-estimate.md)。

## 应用和恢复

新空库初始化会采用这份默认配置。已有站点的普通 seed 不覆盖信源开关，须使用 [信源调整脚本](sources.md#已有站点怎样应用)：先不带 `--apply` 预览，再在对应部署目录应用。脚本自动读取全部明确暂停的 63 个配置，不删除文章，并通过后台更新方法写审计；同时沿用先前六个社区入口的采集配置修正，不主动恢复后台已经暂停的源。

暂停只阻止后续抓取。已进入处理队列的文章不会自动取消，历史公开全文的三语补译仍继续按原要求处理，不能把暂停信源当作历史费用归零。要恢复时，可在后台将对应入口启用；若还会重新执行调整脚本，应同步修改 `industry/sources.json`，避免再次被默认暂停清单关闭。
